A server from zero

ssh-keygen -t ed25519 -C "you@laptop"
# /etc/ssh/sshd_config.d/50-hardening.conf
PasswordAuthentication no
KbdInteractiveAuthentication no
# the default, prohibit-password, lets root in with a key
PermitRootLogin no
AllowUsers deploy
MaxAuthTries 3
X11Forwarding no
# before every restart; keep a second session open
sshd -t

ufw default deny incoming && ufw default allow outgoing
ufw limit 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
# after allowing 22
ufw enable
  • ~/.ssh 700, authorized_keys 600, owned by the user (StrictModes).
  • Log in as deploy; root powers through sudo. The docker group is root-equivalent.
  • Docker's published ports bypass ufw. Never publish internal services; bind to 127.0.0.1 if you must.

Compose in production

x-logging: &logging
  driver: json-file
  options: { max-size: "10m", max-file: "3" }
services:
  api:
    # pinned, built in CI
    image: ghcr.io/you/codearena-api:${TAG:?set TAG}
    restart: unless-stopped
    logging: *logging
    environment:
      # from .env.prod, never in git
      JWT_SECRET: ${JWT_SECRET:?}
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3000/health"]
    networks: [edge, internal]
    depends_on:
      postgres: { condition: service_healthy }
      migrate:  { condition: service_completed_successfully }
networks:
  internal: { internal: true }
  • Only the proxy publishes 80/443. Only the worker mounts the Docker socket (root on the host).
  • migrate: one-shot, restart: "no". Postgres data in a named volume. Memory limit on the worker.
  • docker compose -f docker-compose.prod.yml config validates and shows the resolved file.

HTTPS

  • A certificate binds a public key to names (SAN), signed by an issuer. Clients check: chain to a trusted root, hostname in the SAN, dates.
  • The private key never leaves the server. The CA signs a CSR (public key + names) and chooses the extensions: CA:FALSE, serverAuth, SAN.
  • ACME HTTP-01: serve the token at /.well-known/acme-challenge/<token> on port 80. Let's Encrypt: 90-day certificates.
  • Caddy: DNS pointing at the server, ports 80/443 open, a persistent data volume → certificates, renewals, HTTP→HTTPS redirects.
# read a certificate
openssl x509 -in server.crt -noout -text
# check its chain
openssl verify -CAfile ca.crt server.crt
# see the handshake and the chain
curl -vI https://example.com

From merge to deploy

push to main → test → build (tag: ${{ github.sha }})
             → deploy (environment: production)
deploy.sh <sha>: validate → pull → up -d --wait → curl /health
                 → record | roll back
  • permissions: { contents: read } at the top; packages: write only on build.
  • uses: owner/action@<40-char SHA> # vX.Y.Z (or GitHub's workflow lockfiles).
  • Never ${{ inputs.* }} or ${{ github.event.* }} inside run:; pass through env: and quote "$VAR".
  • known_hosts from a secret; never StrictHostKeyChecking=no.
  • concurrency: { group: production, cancel-in-progress: false }; no deploys from pull requests.
  • Rollback: workflow_dispatch with a tag input → deploy an older SHA.

Seeing production

  • Logs: one JSON object per line: time, level, msg, method, path (no query), status, durationMs, requestId. Never tokens, cookies or Authorization.
  • Health: /health = alive (else restart); /ready = dependencies answer, each check with a timeout (else no traffic, no restart).
  • Metrics: text/plain; version=0.0.4; counters and histograms (cumulative le buckets, _sum, _count); labels with bounded values only (route template, status), never ids.
  • Golden signals: latency, traffic, errors, saturation, plus the judge queue's depth and age.
  • Backups: pg_dump --format=custom nightly, keep 7, copy off the server; restore into a scratch database on a schedule and count rows.
