  • Props server → client must be serializable: primitives, plain objects, arrays, Date, Map, Set, promises, JSX. Not functions or class instances.
  • Whatever a client component receives ships in the RSC payload. Pass ids and small values, never secrets.
  • Push 'use client' to the leaves. Only NEXT_PUBLIC_ env vars reach the browser; import "server-only" guards server modules.
  • JSON inside <script>: escape < as <.

Live updates

  • Polling: setTimeout after each answer (never setInterval); stop on the final state, on unmount (AbortSignal), and on a timeout. TanStack: refetchInterval: (q) => q.state.data?.status === "DONE" ? false : 1000.
  • Cost: users × frequency requests, mostly "no change".
  • SSE: Content-Type: text/event-stream; event: x\ndata: {…}\n\n; : ping heartbeats; EventSource reconnects (and sends Last-Event-ID). Six connections per domain without HTTP/2.
  • Subscribe, buffer, then read. Read-then-subscribe loses what's published in between.
  • Redis Pub/Sub is at-most-once: the database stays the truth; push is an optimisation, polling the fallback.
  • WebSocket when both sides talk continuously (chat, collaborative editing).
