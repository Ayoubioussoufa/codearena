CodeArena’s docker-compose.yml is a good development file: one command, everything up, ports open so your tools can poke at the database. Every one of those conveniences is a production risk. Today you write the file the server will run, one rule at a time, each with the failure it prevents, checked by the same parser Docker uses.

Why this matters

This afternoon this file goes onto the VM you hardened in lesson 21. A firewall can’t save a Compose file that publishes Postgres, and a perfect sandbox can’t save a host whose Docker socket is mounted into the API. This file is where those lessons meet.

1. Read the dev file like a reviewer

Open the lab’s docker-compose.dev.yml, a copy of CodeArena’s. On a laptop, each line is fine. On a server:

  • POSTGRES_PASSWORD: codearena is a secret in git, forever.
  • ports: "5433:5432" and "6379:6379" publish the database and Redis. Docker’s published ports bypass ufw (lesson 21), so they’re on the internet.
  • postgres:16-alpine and dpage/pgadmin4:latest change under you: the server may run something different tomorrow than today.

2. What the server runs, and nothing more

  • Images, never builds. CI builds each image once and pushes it to a registry (lesson 24); the server only pulls. App images use ghcr.io/you/codearena-api:${TAG}, so a deploy is “set TAG, up”, and a rollback is “set the old TAG, up”.
  • Pin everything else. postgres:16.4-alpine, not 16-alpine, and never latest. Upgrades become decisions instead of surprises.
  • Secrets from the environment, loudly. ${POSTGRES_PASSWORD:?set it in .env.prod} takes the value from .env.prod on the server, and if it’s missing, Compose stops with your message instead of starting with an empty password (interpolation). Commit a .env.prod.example listing every variable, with no values.

3. Who can reach what

  • One door. Only the proxy publishes ports, 80 and 443. Containers reach each other by service name on the Compose network: the API connects to postgres:5432 without anything being published.
  • Two networks. An edge network for proxy, web and API; an internal one for the API, worker, Postgres and Redis, declared internal: true, which isolates it from the outside world (networks). The proxy has no route to the database at all.
  • The socket in one place. Access to /var/run/docker.sock is root on the host: it can start a privileged container that mounts /. OWASP’s first Docker rule is not to expose it, even to containers (Docker Security Cheat Sheet). The worker needs it to start runners. Nothing else gets it.

4. Running for months

  • Restart policies. unless-stopped brings services back after a crash or a reboot, but respects a manual stop.
  • Start order that means something. depends_on: [postgres] waits only for the container to start. With a health check on Postgres and condition: service_healthy, the API waits until it answers. A one-shot migrate service, with condition: service_completed_successfully, makes the API start only on a schema that matches its code (services: depends_on). migrate itself never restarts: a failed migration should stay failed, and visible.
  • Disks fill. The json-file log driver’s max-size defaults to unlimited (json-file). Set max-size and max-file on every service; an x-logging extension field with a YAML anchor writes it once (extensions).
  • Blast radius. A memory limit on the worker means a leak kills the worker, not the VM. Postgres’s data lives in a named volume, which outlives every container.

Hint: anchors and merge keys

x-logging: &logging { driver: json-file, options: { max-size: "10m", max-file: "3" } } at the top, then logging: *logging in each service. A second anchor, x-app: &app { restart: unless-stopped, logging: *logging }, merged with <<: *app, saves two lines per service.

6. What this means for CodeArena

  • Keep both files. docker-compose.yml stays the comfortable dev file; docker-compose.prod.yml is what the VM runs. Different jobs, different rules.
  • The worker’s runner containers are started by the host’s daemon, through the socket, with lesson 8’s hardened flags. They aren’t on any Compose network.
  • Today’s done-when is curl http://<vm-ip>/health answering from the VM, with prisma migrate deploy having run through migrate.
