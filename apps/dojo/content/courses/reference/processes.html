The kernel line

A process runs in user mode and can only touch its own memory. Anything else (files, network, other processes, starting programs) is a system call: the CPU enters kernel mode, the kernel checks and acts, then returns. A sandbox is a set of rules on system calls.

Starting a program

  1. fork() returns three ways: -1 it failed · 0 you’re the child · > 0 you’re the parent, and that’s the child’s PID.
  2. Child, in the gap: setpgid(0, 0), redirections (dup2), limits (setrlimit), later namespaces. Then execvp. If it returns, it failed: perror, _exit(127).
  3. Parent: setpgid(pid, pid) too (closes the race), then wait. Always reap, or the child stays a zombie.

Deadlines

  • Two clocks: wall-clock time stops hangs; CPU time measures speed fairly. time shows both (real vs user + sys).
  • Measure with CLOCK_MONOTONIC (C) or performance.now() (Node), never the time of day: it can jump.
  • Wait with a deadline: waitpid(…, WNOHANG) + a 1 ms nap, or pidfd_open + poll.
  • At the deadline: kill(-pgid, SIGKILL), then reap. No grace period.
  • Groups can be escaped (setsid). The real walls are a PID namespace and a cgroup.

File descriptors, pipes, limits

  • 0, 1, 2 = stdin, stdout, stderr. Inherited across fork and kept through exec.
  • Redirect in the gap: open → dup2(fd, 0 or 1) → close(fd). Default stdin for a judge: /dev/null.
  • Pipes: reading an empty pipe blocks while any write end is open; end of file only when all are closed. Writing to a full pipe (64 KiB) blocks. waitpid before reading = deadlock.
  • Output cap: RLIMIT_FSIZE = cap + 1; decide output-limit from the file size, not from how it died.

Look at any process

grep -E '^(Name|State|Pid|PPid)' /proc/<pid>/status
ls -l /proc/<pid>/fd  # what its 0, 1, 2 point to
ps -o pid,ppid,pgid,stat,args -p <pid>
echo $$ ; echo $?     # your shell's PID; how the last command ended
