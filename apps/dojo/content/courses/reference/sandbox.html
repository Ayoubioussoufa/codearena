Namespaces: what it can see

  • Unprivileged containers: create every namespace together with a user namespace; the parent writes uid_map, setgroups=deny, gid_map; the child waits on a pipe until then.
  • PID 1: when it dies, the kernel SIGKILLs the whole namespace. It only receives signals it has a handler for (SIGKILL/SIGSTOP from outside are forced).
  • Files: make / private, set up /dev (tmpfs + bind null, zero, urandom), chroot + chdir("/") (or pivot_root), mount /proc.
# all of it, from a shell

# which namespaces a process is in
ls -l /proc/$$/ns

  • A cgroup is a directory under /sys/fs/cgroup; cgroup.procs lists members; children inherit their parent's cgroup.
  • No internal processes: move yourself into a leaf (supervisor) before writing +memory +pids +cpu to cgroup.subtree_control.
  • Without sudo: systemd-run --user --scope -p Delegate=yes … starts you in a cgroup you own.
  • A CPU limit is not a time limit. Report CPU time; enforce wall time.

The hardened run, and a runner's four decisions

# -i: the input arrives on stdin
docker run -i --name run-<unique> \
  --network none --read-only --tmpfs /tmp:rw,noexec,nosuid,size=16m \
  --memory 128m --memory-swap 128m --pids-limit 64 --cpus 1 \
  --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 \
  -v <tmpdir>:/code:ro  python:3.12-alpine  python3 /code/main.py
  1. Code in: a read-only bind mount (or stdin), never an argument (ps, ARG_MAX).
  2. Image: pinned tag (or digest), never latest.
  3. Name: unique per run, so the daemon can find it.
  4. End: deadline → docker kill <name>; then docker inspect -f '{{.State.OOMKilled}}'; then docker rm -f + delete the folder, in a finally.

Default Docker keeps 14 capabilities (CapBnd 00000000a80425fb), a network, root, and no limits: that's "not a sandbox by default". Startup costs a few hundred ms per run: measure inside, or calibrate with it.
