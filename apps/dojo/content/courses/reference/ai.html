Tokens to text

softmax(z)_i = e^(z_i / T) / Σ e^(z_j / T)     # subtract max(z) first
greedy       argmax of the logits             # T → 0
top-k        keep the k likeliest, renormalise
top-p        keep the smallest set with Σ p ≥ P, renormalise
sample       first index where the running sum > r, r in [0, 1)
  • No memory between calls: everything the model uses is in the request, up to the context window.
  • Hints and evals: low temperature. Even then, run eval cases several times.

Your own model

weights ≈ parameters × bytes      16-bit 2 · 8-bit 1 · 4-bit 0.5
7B at 4 bits ≈ 3.5 GB  (+ KV cache for the context, + runtime)

POST /api/chat  { model, messages, stream: false,
                  options: { temperature, num_ctx }, format: <schema> }
→ message.content, prompt_eval_count, eval_count,
  total_duration, eval_duration          # nanoseconds
tokens/s = eval_count / (eval_duration / 1e9)
POST /api/embed { model, input }  → embeddings
  • Validate the JSON yourself; retry a bad reply once; never retry an HTTP error.
  • Slow on a CPU: the hint is a queued job, not a request.

OWASP LLM01’s layers: constrain behaviour · validate output formats · filter input and output · least privilege · human approval for risky actions · segregate external content · adversarial testing. No single one is fool-proof.

Evals

  • Test set (real and hostile cases) + graders + a score over time.
  • Graders, cheapest first: code rules → a judge model → a human to calibrate.
  • Run each case several times; report the pass rate per rule and the flaky cases; gate CI on a threshold.
                you PASS   you FAIL
judge PASS        TP          FP        TPR = TP / (TP + FN)
judge FAIL        FN          TN        TNR = TN / (TN + FP)
κ = (po − pe) / (1 − pe)                p95 = sorted[⌈0.95 n⌉ − 1]

Judge biases: position, verbosity, self-enhancement. Binary verdicts, swapped orders, a different model family.

Embeddings and vector search

cosine(a, b) = a·b / (|a| |b|)     L2 = √Σ (a_i − b_i)²
pgvector     <-> L2 · <#> −inner product · <=> cosine distance · <+> L1
index        HNSW: better speed/recall, slower build, more memory
             IVFFlat: faster build, less memory, slower queries
             vector up to 2,000 dimensions indexed (halfvec 4,000)
  • Never compare vectors from two embedding models.

RAG

ingest   notes → chunks (by heading, heading repeated) → hash → embed → store
query    facts → top-k chunks → <source id> blocks → prompt → model
measure  recall@k = hits in top k / queries
         MRR      = mean of 1 / rank (0 if missing)
  • Ingestion is idempotent: insert new, update changed, remove gone, skip the rest.
  • recall good, answers bad → the prompt or model; recall bad → retrieval first.
  • Under ~200k tokens of knowledge, you can skip retrieval and send it all.

Better retrieval

BM25(D) = Σ IDF(q) · f(k1+1) / (f + k1(1 − b + b|D|/avgdl))   k1 1.2, b 0.75
IDF(q)  = ln((N − n + 0.5) / (n + 0.5) + 1)
RRF(d)  = Σ 1 / (60 + rank)

Hybrid = BM25 + vectors, fused with RRF. Then a reranker on the top candidates, and contextual retrieval (Anthropic: −35% / −49% / −67% failed top-20 retrievals).

Agents and the levers

  • Tool use: the model asks, your code runs. Unknown tool → refuse; error → feed it back; risky → human approval; a step limit always.
  • Workflow (code sets the steps) before agent (the model sets them).
  • Levers, in order: prompt → full context → retrieval → tools → fine-tuning (LoRA: frozen weights, small trained matrices).
  • MCP: an open protocol that plugs tools and data into any AI app.
