Why this matters

Preprocessing a training corpus means tokenizing millions of documents, each one independent: the kind of work that scales with cores. And the story matters as much as the code. A specific claim backed by your own measurements (“about 25 times faster than pure Python, 5.5 times more on 12 cores”) beats “Rust is the future” every time.

1. rayon: iter becomes par_iter

use rayon::prelude::*;
fn encode_batch(&self, py: Python<'_>, texts: Vec<String>) -> Vec<Vec<u32>> {
    py.detach(|| texts.par_iter().map(|t| self.inner.encode(t)).collect())
}

rayon is a data-parallelism library: par_iter() runs the same chain on a global pool of threads, sized by default to the number of logical CPUs (RAYON_NUM_THREADS overrides it), with idle threads stealing work from busy ones. collect keeps the original order, and it “guarantees data-race free executions” (rayon docs): the closure gets &self, so the borrow rules from lesson 38 still hold. Releasing the GIL first means the Python caller’s other threads keep running too.

It helps only for independent pieces that are each big enough. BPE training is a chain, where each merge needs the counts the previous one left, so the steps can’t run side by side. Measured speedups are rarely the core count: uneven pieces, shared memory bandwidth and the sequential parts all cost time (Amdahl’s law).
