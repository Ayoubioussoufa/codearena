Each is blind where the other sees. Today you build the keyword half from its formula, then fuse the two.

Why this matters

Saturday’s stretch goal is hybrid search. Even if you don’t ship it, “why not just vectors?” is the first follow-up question on any RAG system, and BM25 plus RRF is the standard answer.

1. Keywords, scored properly: BM25

BM25 scores a document for a query by summing, over the query’s words, how much each match is worth (Okapi BM25):

score(D) = Σ  IDF(q) · f · (k1 + 1) / (f + k1 · (1 − b + b · |D| / avgdl))
IDF(q)   = ln((N − n(q) + 0.5) / (n(q) + 0.5) + 1)
  • IDF (inverse document frequency): a word in few documents is worth a lot; one in every document is worth almost nothing.
  • f and k1: more occurrences help, with diminishing returns. k1 (often 1.2) sets how fast it saturates.
  • |D|, avgdl and b: a long document isn’t better for being long; b (often 0.75) sets how much its length counts against it.

Postgres has keyword search built in (tsvector, ts_rank), with its own ranking functions (PostgreSQL: text search); writing BM25 yourself once is how you understand what any of them weigh.

2. Fusing two rankings: RRF

BM25 scores and cosines live on different scales, so adding them is meaningless. Reciprocal Rank Fusion keeps only the ranks (Cormack, Clarke & Büttcher, 2009):

RRF(d) = Σ over each ranking   1 / (k + rank of d)     # k = 60, rank from 1

A document high in both lists wins; one high in a single list still counts; one missing from a list just gets nothing from it. k = 60 was fixed in the original paper and has stayed the usual default. This is hybrid search: run both, fuse, take the top k.

3. On top: reranking and contextual retrieval

  • A reranker is a model that reads the query and each candidate together and rescores it: slower than an embedding, much sharper. Retrieve 50 fast, rerank, keep 4.
  • Contextual retrieval prepends to each chunk a short explanation of where it sits in its document, before embedding it and before indexing it for BM25.

Anthropic measured the steps on top-20 retrieval failures (contextual retrieval): contextual embeddings alone, −35%; plus contextual BM25, −49%; plus reranking, −67%. Each layer earns its place with a number. Yours should too.
