Why this matters

Memory-safety bugs were 76% of Android’s vulnerabilities in 2019. Google started writing new code in memory-safe languages, Rust among them, and by 2024 the share was 24% (Google Security Blog, Sept 2024). And the honest AI angle, for lessons 40–42: the AI work itself happens in Python, but more and more of the fast parts underneath are Rust (Hugging Face’s tokenizers, the uv package manager). That’s where you’ll use it.

1. Install Rust

rustup installs and updates the toolchain: rustc (the compiler), cargo (the build tool and package manager), and the standard library’s docs. It’s the official way (rust-lang.org/tools/install). Rust uses your system’s linker, the cc you already use for the C labs.

1

Install, then check

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# accept the default install, then open a NEW terminal
rustc --version     # 1.99 or later
cargo --version

In VS Code, install the rust-analyzer extension: it runs the compiler’s checks as you type and shows types inline. Later, rustup update moves you to each new release, every six weeks.

2. Cargo, your pnpm

A crate is Rust’s unit of compilation: a library or a program. Cargo builds crates, fetches their dependencies from crates.io, runs tests and docs. Cargo.toml is your package.json; Cargo.lock pins exact versions, like pnpm-lock.yaml.

cargo new hello        # a program: src/main.rs  (cargo new --lib: src/lib.rs)
cd hello
cargo check            # types and borrows only, no binary: fastest feedback
cargo run              # build (debug) and run
cargo test             # build and run every #[test]
cargo build --release  # optimized binary in target/release/

Two build profiles matter. Debug (the default) compiles fast and keeps safety checks such as integer overflow. Release optimizes hard. Benchmark only release builds; lesson 42 shows the gap.

3. The basics you need today

Immutable by default. let x = 5; can’t change. let mut x = 5; can. Most variables in good Rust never need mut, and when you see one, it tells you to watch it.

Shadowing. A second let x declares a new variable that hides the first, and may change its type: let n = "42"; let n: i32 = n.parse().unwrap(); is normal Rust. (unwrap() means “crash if this failed”; lesson 32 replaces it.)

Integer types say their size. i32, i64, u8 (a byte), usize (a length or index). No silent conversion: x as i64 converts on purpose.

Overflow is defined. In a debug build, 255u8 + 1 computed at runtime panics: the program stops with a message, instead of continuing with a wrong value. A release build wraps to 0. If you mean wrapping, write wrapping_add; checked_add returns None on overflow (The Book, §3.2). In C, signed overflow is undefined behaviour.

Almost everything is an expression. A block’s value is its last expression without a semicolon. So if returns a value, and a function needs no return at the end:

fn sign(n: i32) -> &'static str {
    if n < 0 { "negative" } else { "not negative" }   // no semicolon: the value
}

Add a semicolon after the if and the block’s value becomes (), the empty “unit” value, and the compiler says mismatched types. You’ll make that mistake today; the compiler’s help line tells you which semicolon to remove.

5. Reading the compiler

Rust’s errors have a shape worth learning once:

error[E0384]: cannot assign twice to immutable variable `x`   ← the code, then what
 --> src/lib.rs:3:5                                            ← file:line:column
  |
2 |     let x = 0;
  |         - first assignment to `x`                          ← labels point at the story
3 |     x = status & 0x7f;
  |     ^^^^^^^^^^^^^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable                     ← often the fix itself
  |
2 |     let mut x = 0;
  |         +++

Every error code has a long explanation with examples: rustc --explain E0384 (online index). Fix the first error first; later ones are often its echoes. The lab’s checker shows you only that first one, on purpose.
