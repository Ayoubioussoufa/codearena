In lesson 2 you wrote run -t in C: fork, exec, a monotonic clock, waitpid with WNOHANG, a process group, one kill to end them all. Today you write the same program in Rust, and lesson 2’s own checker grades it, case for case. Most of the C turns into safe library calls. One line stays a raw system call, and that line teaches you what unsafe really means.

Why this matters

This is where Rust earns its place in infrastructure: the same control over processes and signals as C, without the buffer and lifetime bugs around them. Comparing your two versions line by line is also an interview story: “I wrote the sandbox runner in C, then in Rust, and here’s which bugs each one could still have.”

CommandExt and ExitStatusExt live in std::os::unix::process: extension traits (lesson 33) that add Unix-only methods to portable types (CommandExt, ExitStatusExt). spawn reports a failed exec back to the parent as an Err, so you never hold a Child that didn’t really start.

2. The one line std can’t do

Child::kill sends SIGKILL to the child alone. Its children survive, which is lesson 2’s escape. Signalling a whole group needs kill(2) with a negative PID, and std doesn’t wrap it. So you call it through the libc crate, which declares C’s functions for Rust:

// SAFETY: kill(2) with a negative pid signals a process group.
// It reads no memory of ours; the worst it can do is fail.
unsafe {
    libc::kill(-pgid, libc::SIGKILL);
}

Calling a foreign function is unsafe because the compiler can’t see inside it. What unsafe does not do is switch anything off: the borrow checker and type checks still run inside the block. It allows a handful of extra operations (dereferencing a raw pointer, calling an unsafe or foreign function, using a mutable static, implementing an unsafe trait), and you promise they’re sound (The Book, §20.1). The // SAFETY: comment is the promise in writing; the standard library writes one above every unsafe block. The nix crate wraps calls like this one in safe functions, if you’d rather not write the block yourself.

3. Build run

The same contract as lesson 2: run -t <ms> <program> [args…] prints “exit N”, “signal S” or “timeout”, then time_ms=N; at the deadline it kills the whole group; called wrong, it prints nothing on stdout and exits 2. One addition: a program that can’t be started prints exit 127, as a shell would. check.sh is lesson 2’s checker, building your Rust binary instead of run.c, with lesson 2’s test programs in progs/.

Spawn, poll, kill, report

Start the clock, spawn with .process_group(0) (on Err, report exit 127), then loop on try_wait(): a status means report it; past the deadline means kill the group, wait() to reap, report timeout; otherwise sleep 2 ms. A match on (status.code(), status.signal()) picks the line. All three “Nothing left behind” cases need the group kill.
