Deciding one test, in order

#The runner's facts sayVerdict
1timeoutTLE Time Limit Exceeded
2memory-limit (OOM kill: OOMKilled / oom_kill)MLE Memory Limit Exceeded
3output-limitOLE Output Limit Exceeded
4a signal, or an exit code other than 0RE Runtime Error (output not read)
5exit 0, tokens differWA Wrong Answer
6exit 0, tokens matchnext test; all pass → AC
  • Stop at the first failure; report its number (1-based) and the slowest time among the tests that ran.
  • Your failure is not a verdict. Docker down, database down: throw, let the queue retry, dead-letter after the last try.
  • No tests is a bug, never an Accepted.

The token checker

// spaces, tabs, \n, \r all separate
tokens(s) = s.split(/\s+/).filter(Boolean)
// "1.0" ≠ "1", "YES" ≠ "yes"
match     = same length, and equal at every index

Codeforces' standard checker wcmp (testlib) does the same. Floats need a checker with a tolerance; "any valid answer" problems need a custom checker.

Limits

  • Calibrate on the reference solution: measure, then a few times that. Count container startup the same way in calibration and in production.
  • Report CPU time (cgroup cpu.stat) as the run's time; enforce wall time as the deadline.
  • Never show one user another user's stderr; cap it like stdout.
