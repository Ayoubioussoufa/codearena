In lesson 9 you turned runner facts into verdicts in TypeScript, with a string union and a chain of ifs. Today you write the same judge in Rust, where a verdict is an enum whose variants carry their own data, and every decision is a match the compiler checks for completeness. Forget a case, and it doesn’t compile.

Why this matters

Most production bugs in a judge are a case nobody handled: the crash after the right output, the timeout that also ran out of memory. Rust’s enums turn “did we handle every case?” from a code-review question into a compiler error, and that idea, making illegal states impossible to build, is worth carrying back to your TypeScript.

1. Structs and enums

A struct groups named fields, like C’s. An enum is one of several variants, and unlike C’s, each variant can carry its own data (The Book, §6.1):

enum Ending {
    Exited(i32),     // a tuple-like variant: the exit code
    Signaled(i32),   // the signal number
    TimedOut,        // no data
}
enum TestVerdict {
    Passed,
    WrongAnswer { token: usize },   // a struct-like variant
    RuntimeError(Ending),           // variants can hold other enums
    // ...
}

In memory, it’s a tag plus room for the largest variant: C’s tagged union, except the compiler won’t let you read the wrong member. #[derive(Debug, PartialEq)] above a type asks the compiler to write printing and == for it.

2. match: the only way in

To use a variant’s data, you match on it. Arms are tried top to bottom; the first whose pattern fits, and whose guard (if …) is true, runs. And the match must be exhaustive: every possible value covered, or it’s error E0004 (§6.2).

match facts.ending {
    Ending::TimedOut => TestVerdict::TimeLimit,
    _ if facts.oom_killed => TestVerdict::MemoryLimit,   // guard: order matters
    Ending::Exited(0) => compare(expected, &facts.stdout),
    Ending::Exited(_) | Ending::Signaled(_) => TestVerdict::RuntimeError(facts.ending),
}

That match is lesson 9’s order of checks. match is an expression, so its arms produce the result, and they must all have the same type. if let Some(x) = opt { … } is the short form when you care about one pattern only.

3. Option: no null

Rust has no null. A value that might be missing is an Option<T>, an ordinary enum: Some(value) or None. You can’t use the value without dealing with None, so “undefined is not a function” has no Rust equivalent. first_difference returns Option<usize>: None means the outputs match.

5. Make illegal states unrepresentable

When you write describe, the compiler makes you handle Failed { why: TestVerdict::Passed } and RuntimeError(Ending::TimedOut). Neither can happen, but the types allow them, so you write arms for nonsense. The fix isn’t a comment or an assert: it’s types that can’t express the nonsense. A failure reason enum without Passed; a crash enum with only Exit(i32) and Signal(i32). Then the impossible arms disappear, and so do the bugs they could hide. The phrase comes from Yaron Minsky’s “Effective ML” talk, and it applies to TypeScript just as well.
