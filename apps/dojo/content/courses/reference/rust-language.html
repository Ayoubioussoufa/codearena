Bindings, types, expressions

  • let x = 5; is immutable. let mut x can change its value, never its type. A second let x shadows: a new variable, possibly of a new type.
  • Integers say their size: i8…i128, u8…u128, isize/usize (pointer-sized: lengths and indexes). Floats: f32, f64. Also bool, and char (a Unicode scalar, 4 bytes).
  • No silent conversions: x as i64 (may truncate), i32::try_from(x) (checks).
  • A block’s value is its last expression without a semicolon. if, match and blocks are expressions; both arms of an if must have the same type.
  • Precedence: & ^ | bind tighter than ==, so s & 0x7f == 0 means (s & 0x7f) == 0. (C has it the other way round.)

Reading an error

error[E0384]: what → --> file:line:col → labelled source lines → help:, often the fix itself. Fix the first error first: the rest are often its echoes.

Ownership (lesson 29)

  1. Each value has one owner. When the owner goes out of scope, the value is dropped (freed), once.
  2. let t = s; moves a non-Copy value: s is unusable after (E0382). Passing to a String parameter or v.push(s) moves too.
  3. Copy types (integers, bool, char, shared references, tuples of these) are copied instead.
  4. .clone() = a second, independent allocation. Right when you need two owners; wrong to silence the compiler.
  5. std::mem::take(&mut s) moves a value out and leaves its default (an empty String) behind, with no allocation.

Borrowing (lesson 30)

  • Any number of &T, or exactly one &mut T, never both. A borrow lasts until its last use.
  • References never outlive their owner. Holding &v[0] across v.push(…) is E0502: push may reallocate.
  • Parameters: read text &str, read a list &[T], change in place &mut String / &mut Vec<T> / &mut [T], keep it String / Vec<T>. Never &String.
  • Slices (&s[a..b], split_whitespace()) point into their owner: no copy.

Enums and match (lesson 31)

enum Ending { Exited(i32), Signaled(i32), TimedOut }
match facts.ending {
    Ending::TimedOut => …,
    _ if facts.oom_killed => …,          // guard; first matching arm wins
    Ending::Exited(0) => …,
    Ending::Exited(_) | Ending::Signaled(_) => …,
}
  • Matches must be exhaustive (E0004); guards don’t count towards it. if let / let … else for one pattern.
  • Option<T> = Some(T) | None: Rust’s replacement for null.
  • Make illegal states unrepresentable: if a combination can’t happen, design types that can’t hold it.

Lifetimes (lesson 34)

  • fn longest<'a>(a: &'a str, b: &'a str) -> &'a str: the result can’t outlive either input. Annotations describe; they never extend a life.
  • Elision: (1) each input reference gets a lifetime; (2) one input lifetime → outputs get it; (3) &self methods → outputs get self’s. Otherwise E0106.
  • A struct holding a reference: struct Tokens<'a> { rest: &'a str }. Return &'a str from its methods when the result borrows the input, not the struct.
  • 'static: lives for the whole program (string literals). E0597: “does not live long enough”.

Iterators, closures, maps (lesson 35)

  • Closures: only reads → Fn; changes a capture → FnMut; moves one out → FnOnce. move changes how values are captured, not which trait.
  • Adaptors are lazy (map, filter, filter_map, enumerate, take_while, skip, rev, windows(2) on slices); consumers pull (sum, count, max, min_by_key, position, any, fold, collect).
  • *map.entry(k).or_insert(0) += 1; · map.entry(k).or_default(): one lookup, update in place.
  • HashMap order is random per run; use BTreeMap or sort. Multi-key sort: a.x.cmp(&b.x).then(b.y.cmp(&a.y)).
